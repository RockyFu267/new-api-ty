# 聊天临时附件与上下文面板

确认时间：2026-10-20。

## 范围

- 聊天页的公共知识库、私有知识库、Skill 可分别展开和收起，标题保留已选数量；收起不取消选择、不改变是否启用。
- 附件按钮选择文件；输入框支持粘贴剪贴板里的截图或文件，普通文字粘贴不变。浏览器或操作系统未向剪贴板提供文件时，使用附件按钮选择。
- 文本仅支持 `.log`、`.txt`、`.md`，使用 UTF-8 编码，单文件不超过 10 万字符；图片支持 PNG、JPEG、WebP、GIF，按文件内容识别 MIME。
- 每条消息最多 6 个附件，每个不超过 5 MB。不支持 PDF、Word、Excel 等格式。
- 发送前显示附件名、图片缩略图，可逐个移除；仅有附件时也可发送。读取中禁止发送，失败保留此前已添加附件。
- 文本在浏览器读取，聊天消息仅显示文件名，不展开正文；发送给模型时再合并文件名和正文。图片使用标准 `image_url` data URL 随消息发送。历史消息保留原附件，支持继续追问和重试，发送后的消息中可看到图片。
- 页面明确提示图片需要视觉模型；模型是否实际支持图片由所选上游决定，供应商返回的错误沿用现有聊天错误展示，不按模型名称猜测能力。

## 数据生命周期

- 使用聊天页现有内存消息状态，不新增上传接口、文件库、数据库表或浏览器持久化。待发送附件发送后清除；当前会话中的消息附件在清空、退出当前模型会话或刷新后释放。
- 网关 `/pg/chat/completions` 入站正文、服务器知识库/Skill 注入后的替换正文、各模型转换后的出站正文及图片解码缓存均强制使用内存，即使管理员打开磁盘缓存也不落盘。
- 聊天请求不输出调试正文日志，也不写参数覆盖内容审计，原有金额、Token 用量和权限审计保留。Dify 原先冗余的图片临时文件写入已去除，沿用内存构造 multipart 请求。
- 图片和文本仍会作为推理内容发给所选上游服务；不改变供应商自身的数据保留政策。
- 部门模型授权、分组、配额、钱包和定价计算继续沿用原逻辑。

## 验证

- 前端覆盖文本读取、格式/大小限制、伪图片拒绝、图片数据格式、历史消息图片保留、上传和粘贴、移除和清空、面板折叠保留选择，以及实际聊天输入框发送的模型/渠道/文本/图片完整载荷。
- 后端覆盖磁盘缓存开启时聊天入站、替换正文、出站重放和 Base64 图片源仍使用内存。
- 验证结果：聊天与 Playground 18 项前端测试、类型检查、相关 lint、生产构建和 Go 编译通过；common、relay（含供应商适配器）、controller、middleware、logger 及 service 文件处理相关测试通过。额外 HTTP/2 重试测试曾出现 Windows 本机连接中断，单独复测通过。
- 本批完成代码实现与本地验证；服务器部署单独执行。
