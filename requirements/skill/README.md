# Skill 展示 Demo 需求

## 目标

在 TIANYAN 内部演示平台中提供一个直观的“大模型 + Skill”案例：用户在 Chat 中启用“企业展示屏设计师”Skill，用自然语言要求切换风格或更新内容，模型理解需求后生成受控指令，本地展示页随即发生变化。

## 功能范围

- 在 Chat 对话页提供 Skill 开关及“打开展示页”入口。
- 新增独立的“Skill 展示页”，从本地 `demo/skill-showcase.json` 读取标题、提示、指标、亮点和主题。
- 内置科技蓝、管理驾驶舱、绿色运维、AI 创新四个模板，模型根据用户描述选择模板，也可以更新模板中的展示文案和指标。
- Skill 开启时，平台向渠道模型注入操作说明；模型在助手回复末尾生成 `tianyan-skill` JSON 指令。
- 在“系统设置 → 运维 → Skill 管理”提供独立管理入口，管理员可以修改 Skill 名称、用户说明、系统提示词以及启用状态。
- Skill 配置保存在本地 `demo/showcase-skill.json`；保存后对后续新对话立即生效，不需要重新编译前端或重启服务。
- 管理员停用 Skill 后，普通用户的 Chat 不再显示该 Skill；后端同时拒绝已停用 Skill 的调用，不能只依赖 UI 隐藏。
- 前端仅从已完成的助手回复中识别该指令，并提交给后端执行；执行成功后展示页通过轮询在约 1 秒内更新。
- 考虑本地模型及部分渠道模型可能只口头回复“已修改”而不严格输出结构化指令，前端兼容专用代码块、XML 包装和 JSON 代码块；当本轮明确提到四个预设风格时，允许本地受控逻辑兜底切换对应模板。
- 无法识别任何安全指令时必须提示用户“未执行”，不得让模型的口头回复造成已经修改成功的假象。

## 安全边界

- 模型不能直接写文件，也不拥有 Shell 或任意脚本能力。
- 后端执行器只接受 `update_showcase` 动作，只能写入固定的 `demo/skill-showcase.json`。
- 模板名称、字段、文本长度、指标数量和亮点数量均由后端校验；不接受文件路径、命令或其他动作。
- 本功能用于内部 Demo，不等同于生产级通用 Agent 执行框架。

## 实现状态

截至 2026-09-09，受控 Skill 指令链路、本地配置、四套模板、Chat 开关、实时展示页和独立 Skill 管理页面已完成实现，等待界面验收。
