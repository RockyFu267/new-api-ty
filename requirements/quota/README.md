# 企业部门配额与钱包兜底

## 2026-10-14：范围与规则

- 新增管理员导航“部门配额”“钱包变动记录”。部门配额针对部门内每个人，不是共享额度池。
- 企业配额模式默认关闭，确保升级不会自动改变现有钱包／订阅的资金来源选择。管理员先配置部门规则，再开启模式。
- 模式开启后，普通同步中继请求固定优先使用部门配额；没有部门、没有启用配额规则、或预估额度不足时，整笔尝试钱包。两者都不足时停止请求，用户计费偏好不能绕过此顺序。
- 日／周／月上限以金额配置，使用现有系统货币展示与额度换算；数据库保存现有整数 quota 单位。模型价格、缓存计价、倍率及计费表达式保持不变。
- 某个周期未配置表示不限制该周期；至少一个周期配置正数才能启用公司配额，全部未配置不表示无限使用。
- 日、周、月同时生效。按北京时间每日 00:00、每周日 00:00、每月 1 日 00:00 计算新周期，不累积未使用的额度。
- 周跨月时保持完整的周日到周日；月初只刷新月额度，不刷新当前周额度。
- 采用独立的请求预占／结算／退款记录，并在数据库事务中锁定用户，防止多个请求重复占用同一剩余额度。
- 实际消费同时累计到对应日、周、月，账单只记录一次。钱包消费不占用部门配额。
- 请求归属于开始时的周期及部门；跨周期完成仍归原周期，变更部门不清空历史个人配额用量，历史部门名称保留。
- 上限控制新请求准入，预估与上游实际消费可能不同；已经进入上游的请求按实际费用完整结算，不丢账、不暗中拆账扣钱包。进行中的消费可能导致实际使用超过上限，此后请求尝试钱包或停止。
- 首版保持异步媒体任务、Realtime 等旧计费路径：异步任务不使用部门配额，继续走钱包；现有任务调整／退款不会误扣公司配额。企业配额主要用于当前业务的同步文本 Chat、Agent/API 请求。
- 服务中断造成尚未结算的预占不会擅自退款，当前周期内仍占用额度，下一周期的可用额度按新窗口计算。

## 页面

- 部门配额：启用模式、编辑部门规则、按部门和用户查看日／周／月消费与钱包余额、查看用户独立账单。
- 用户管理：新增“查看配额”；现有钱包调整添加可选申请／审批备注。企业模式下调整余额采用事务，保存准确的前后余额到现有管理审计。
- 钱包变动记录：查询操作人、目标用户、部门、操作类型、前后余额、备注；支持关键字、操作和日期筛选。旧审计未保存的字段显示空值，不推算历史余额。
- 用户“额度与钱包”：展示钱包余额、本月钱包消费、配额上限／已用／预占／剩余／刷新时间；配额和钱包消费明细分别查询。
- 隐藏普通用户的在线充值、兑换码、推荐奖励及奖励转钱包入口，保留旧实现和数据；钱包额外预算通过管理员调整。
- 使用日志增加扣费来源展示与筛选，日志统计使用同一筛选；既有 token、请求次数、总消费统计继续复用。
- 管理员钱包变动审计与消费账单分开。配额账单来自独立主账，不依赖消费日志开关；token、缓存等细节从已有消费日志补充。日志不存在时不把未知 token 数伪装成 0。钱包消费明细继续依赖原有消费日志开关。
