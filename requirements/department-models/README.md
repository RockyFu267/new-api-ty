# 部门模型权限与部门策略

确认日期：2026-10-19。

## 已确认规则

- 管理员按部门维护允许调用的模型清单，用户继承所属部门的清单，不增加个人例外。
- 未分配部门、部门尚未配置清单、清单为空：均禁止调用任何模型。
- 普通用户、管理员、超级管理员遵守同一调用限制；管理页面和策略配置权限不受是否可以调用模型影响。
- 钱包余额、API Key、原有 default/vip/svip 分组均不能扩大部门模型范围。模型权限与企业配额模式开关独立，关闭配额模式不关闭模型权限。
- 可用模型是部门白名单、原有分组及渠道可用性、API Key 限制的交集。先通过模型授权，再沿用原配额和钱包计费。
- 按客户端可见的完整模型名精确授权；渠道内部的上游模型映射不改变授权对象。不支持自动授权新模型或通配符授权。
- 调部门、修改授权后，新请求实时查询数据库，无跨节点缓存延迟；已开始请求使用请求内授权快照，重试、流式输出和已提交异步任务可继续完成。新的 remix/续作仍需重新授权。

## 页面与接口

- 原“部门配额”入口更名“部门策略”，保留 `/department-quotas` 路径；包含原周期配额、用户用量及新增“模型权限”页签。
- 模型权限展示每部门授权清单及数量；管理员可搜索多选、勾选搜索结果、清空全部、保存。清空表示全部禁止，页面显式提示；保存失败保留输入。
- 管理员接口 `GET/PUT /api/user/company-quota/models`，维护策略、模型配置目录并记录操作审计。配置目录不代表调用权限。
- Chat 渠道模型列表、个人可用模型、API 的 `/v1/models`（含 Gemini/Anthropic 格式）、单模型查询均执行部门授权。
- Chat 的指定渠道调用、API 的指定渠道/自动分组、OpenAI/Responses/Claude/Gemini、embedding 等正常转发入口，在转发和计费前鉴权。异步提交及续作在实际模型解析后再次鉴权。
- 拒绝重复的顶层 model/group 参数，避免渠道选择和请求解析使用不同模型。权限拒绝响应包含 `department_model_forbidden`；前端空模型状态提示联系管理员确认部门授权和可用渠道。

## 数据与上线

- 主库新增 `department_model_policies`，每部门一行、模型清单存为 JSON 文本；通过现有迁移自动建表，支持 SQLite/MySQL/PostgreSQL。
- 不预填任何授权，不修改既有部门成员、渠道、分组、余额、周期配额或计费计算。删除部门时在同一事务删除对应模型策略。
- 本次代码尚未部署；部署后现有未配置授权的部门也会立即默认禁止。管理员仍可进入部门策略页面，为自己及其他部门配置授权。

## 验证

- 后端：无部门/无策略/空策略拒绝、模型精确匹配、部门变更、授权撤销、角色无豁免、API Key 限制交集、指定渠道防绕过、主流转发路径和重复模型参数。
- 前端：默认拒绝提示、搜索后多选只授权选中模型、清空保存空清单、失败后保留编辑内容；保留原配额和钱包页面回归。
- 验证结果：model/controller/middleware/relay 测试通过；前端相关 8 项测试、类型检查、相关 lint、生产构建及 Go 编译通过。service 测试仍有既有的两个 channel affinity 缓存统计测试失败（MixedMode、UnsupportedModeKeepsEmpty），未修改相关逻辑。
