## 数据复制及隔离

`pg_dump` 使用一个保持打开的只读 REPEATABLE READ 导出快照；在线读源，使用 `pg_restore --single-transaction` 恢复到新测试库。未使用生产库作为 CREATE DATABASE TEMPLATE，因此无需断开生产连接。

快照为 50 张表、208 位用户、216,603 条日志、213,706 条部门计费记录。恢复后逐表行数一致，用户钱包／累计扣额／请求数、消费日志扣额／输入输出 Token、部门预扣与结算分组金额、全部 options 的内容哈希一致。dump 约 1.287 秒，restore 约 3.161 秒。含凭据的临时 dump 在验证和测试副本隔离完成后删除，仅保留哈希及清单。

以下只修改测试副本：

- 禁用真实渠道、清除渠道密钥、将上游指向本机不可用端口，保留渠道模型定义及所有计价配置。
- 轮换测试副本 API Key，清除复制的登录会话、双因素与第三方登录绑定；原用户密码在测试副本禁用，仅保留新的本地测试管理员。
- 移除测试副本的 AD/SMTP/OAuth/支付相关连接配置，关闭注册。不会通过生产 AD、邮件或付费模型做自动化测试。
- 保留用户／部门／模型权限／余额／配额／使用日志／计费快照。历史用户名与账号 ID 在使用记录中保留。
- 本地构建绑定 loopback，关闭凭据自动刷新、订阅重置及系统定时任务执行。所有这些行为与之前的本地隔离构建一致。

业务测试库是复制时刻的独立快照，不会持续同步生产，也不会向生产回写。本地登录等操作会继续产生测试数据。
