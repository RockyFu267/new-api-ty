# 知识库、Skill 与 MCP 集成需求评估

## 背景

TIANYAN 内部 Demo 需要展示 Chat 不仅能够调用指定渠道模型，还可以按管理员配置使用内部运维知识。首个演示场景是用户询问 K8s 集群信息，模型根据授权知识回答；管理员可以决定用户是否能够下载知识库原始文件，或仅允许通过 Chat 间接使用。

## 2026-09-02：首阶段知识库 Demo

### 样例数据范围

- K8s 目录首阶段只允许纳入 `knowledge-base/k8s/k8s-clusters.md`。
- SSH 目录可作为待管理的数据来源，但不能默认将所有文件直接送入模型或开放下载。
- SSH 目录当前包含私钥和明文认证信息。私钥、密码、Token 等凭据必须被识别为机密，不得进入模型上下文、引用内容、浏览器响应、下载接口或普通应用日志。

### 管理能力

- 管理员可以创建知识库，添加或选择文档，并查看文档处理状态。
- 管理员可以把一个或多个知识库绑定到指定“渠道 + 模型”组合。
- 每个知识库文件可以独立设置是否允许用户直接下载原文；该设置只控制下载能力，不代表内容对模型不可见。
- 下载权限必须由后端校验，不能仅通过隐藏前端按钮实现。
- 管理员能够停用知识库或解除其与渠道模型的绑定。
- 知识检索、下载和配置变更应留下审计记录。

### Chat 展示与行为

- 渠道模型选择页或聊天页应明确显示已接入的知识库。
- 用户提问后，服务端检索当前用户及当前渠道模型被授权使用的内容，并将结果作为受控上下文交给模型。
- 回答应展示知识来源名称或引用片段，形成可感知的知识库 Demo 效果。
- 允许下载时展示并提供原始文件下载；禁止下载时不返回原始文件地址。
- 禁止下载不能阻止模型在回答中复述其已读取的知识内容，因此不能作为保密手段；敏感凭据必须在入库前排除或脱敏。

### Demo 实现建议

- 第一阶段数据量很小时，不强制引入向量数据库。可以先做 Markdown 文档解析、分段、关键词检索和受控上下文注入。
- 为增强演示效果，首阶段提供知识库管理页、渠道模型绑定、下载策略、Chat 知识库标识、引用来源和审计记录。
- 后续数据量和语义检索需求增加后，再替换为 Embedding 与向量检索；权限模型和 Chat 接口保持不变。

### 验收场景

1. 管理员创建“K8s 集群资料”知识库，纳入 `k8s-clusters.md`，绑定本地 Qwen 或 AWS Bedrock 渠道模型。
2. 用户询问“现在有几套 K8s 集群”或“办公室集群有哪些节点”，模型基于文档正确回答并展示来源。
3. 管理员开启原文下载后，授权用户可下载该文档；关闭后不提供直接下载，但用户仍可通过 Chat 使用其中的授权知识。
4. 未绑定知识库的渠道模型不使用该知识回答；无权限用户无法通过修改请求参数绕过限制。
5. SSH 私钥和认证凭据不会被入库、返回或下载。

### 已废弃的固定案例实现

2026-09-02 首次实现曾将 K8s 文档和渠道模型直接绑定。经需求澄清，该产品模型不符合预期，已废弃并重构，不再作为当前验收依据。

- 系统首次迁移时自动创建“企业内部 K8s 信息库”，内置内容只取自已审核的 `k8s-clusters.md`，不读取 SSH 目录。
- 管理员可在旧版固定案例页面配置原文下载开关；该开关只控制直接下载。
- 知识库和渠道模型绑定保存在服务端数据库，按渠道 ID 与模型名称联合识别。
- 用户渠道模型列表会显示知识库名称、来源及下载策略；Chat 页面持续展示当前接入的知识库。
- Chat 请求命中已绑定渠道模型时，服务端将 K8s 知识作为受控系统上下文注入，并要求模型基于资料回答、标注来源；未绑定的渠道模型不会收到该内容。
- 原文下载接口会在服务端重新校验下载开关；关闭下载时不能直接取得原始文件。
- 已增加实际请求体注入测试，验证模型收到 K8s 内容，而不仅是前端显示绑定状态。

## 2026-09-02：通用目录与文件选择需求（取代固定 K8s 案例）

- 知识库来源是服务端 `knowledge-base` 目录，不允许在产品代码中按 K8s、SSH 等案例硬编码。
- 管理员通过管理平台扫描目录，并细致控制其中哪些 Markdown 文件对用户开放。
- 每个开放文件可以独立设置是否允许下载原文；关闭下载不构成内容保密承诺。
- 用户进入任意渠道模型的 Chat 后，可以按目录勾选全部已开放文件，也可以细致勾选一个或多个 Markdown 文件。
- 每次请求必须携带用户本次选择的文件 ID；服务端重新校验文件仍处于管理员开放状态，不能信任前端提交的路径或内容。
- 服务端只对本次选择的文件进行分段和问题相关性过滤，将命中片段作为模型上下文；没有勾选时不得注入知识。
- 模型回答应列出实际使用的相对文件路径作为知识来源。
- 目录选择是前端对该目录下可用文件的批量选择，不授予目录中未开放文件的访问权限。
- 扫描只接收根目录以内、非符号链接、大小受限的 `.md` 文件，防止路径穿越或把私钥等非 Markdown 文件误送给模型。
- K8s 正确回答只是首个验收场景：管理员开放 `k8s/k8s-clusters.md`，用户在 Chat 勾选后能够询问集群数量、节点及版本信息。

当前实现状态：截至 2026-09-02，已按上述通用模型完成重构：

- 管理端支持扫描 `knowledge-base` 目录并逐个设置 Markdown 文件是否对用户开放、是否允许下载。
- Chat 会加载当前已开放文件，按相对目录分组；用户可勾选目录或任意多个文件。
- 本次勾选的文件 ID 随请求提交，服务端再次校验管理员白名单，并对文档分段、按问题关键词相关度选择片段后注入模型上下文。
- 注入上游前会移除平台私有的文件 ID 参数，避免将内部控制字段透传给模型供应商。
- 下载接口只接受服务端文件 ID，并重新校验启用、文件存在和下载开关；关闭下载的文件不提供原文下载。

## 2026-09-02：取消“黑盒”表述

- Chat 页面不再显示“黑盒”字样，管理端只保留准确的“允许下载”开关。
- 原因：模型获得知识片段后，用户可能通过直接询问或多轮提问让模型复述内容，平台无法把“禁止下载”等同于“内容不可提取”。
- 真正的保护边界必须建立在“模型能够接触哪些内容”上：机密内容不得入库；受限内容需要按用户或 AD 组授权；凭据类信息应改由受控工具按最小必要结果返回，而不是作为文档上下文提供给模型。
- 扫描限制为知识库根目录内的非符号链接 `.md` 文件，单文件最大 1 MiB；不扫描私钥等其他文件类型。
- 已通过后端选择/白名单注入测试、前端目录与文件展示测试、类型检查、代码检查和生产构建。

## Skill 集成评估

- 可以实现。Skill 可定义为一组由管理员维护的系统指令、操作步骤、输入约束和可选工具绑定，并分配给指定渠道模型或用户范围。
- Demo 阶段可先实现只读型 Skill，例如“K8s 信息查询助手”：固定行为说明、绑定知识库、展示 Skill 标识，不执行真实运维命令。
- 后续如允许 Skill 执行操作，必须增加参数校验、用户确认、命令白名单、权限隔离、超时和完整审计。

## MCP 集成评估

- 可以实现，但复杂度和风险高于知识库与只读 Skill。
- 平台需要实现 MCP 服务配置、连接检测、工具发现、工具参数转发、结果回填、渠道模型工具调用适配以及用户/模型级授权。
- 执行类工具需要区分只读和变更操作；高风险调用应要求显式确认，并具备超时、并发限制、网络边界、凭据托管和审计。
- Demo 建议先接入只读 MCP 工具，例如查询集群清单或模拟查询节点状态，不直接开放 SSH 私钥和任意命令执行。
