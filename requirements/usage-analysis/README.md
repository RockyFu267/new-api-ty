# 管理员用量分析

需求确认：2026-10-19。入口名称为“用量分析”，仅管理员可见，普通用户页面不增加功能。

## 已确认范围

- 统计公司、部门、人员、模型的 Token 用量，包含输入、输出、缓存读取、缓存写入和请求次数；可组合筛选、按部门到人员到模型下钻，并导出 CSV。
- 今日、本周、本月累计；最近一年完整自然月的月均值；最近一个月完整日的日均、周均值。包含零用量日期，平台运行不足统计周期时显示实际覆盖数。
- 北京时间，每日零点、每周日零点、每月 1 日。跨月的周保持完整，周趋势不按月份切开。
- 请求开始时保存部门归属；调部门、重命名或删除部门，不重写历史汇总。旧日志无法还原部门时单列“历史部门归属未知”；新请求确实无部门时单列“未分配部门”。
- 2026-10-19 筛选反馈补充：页面默认采用“当前部门人员（包含历史用量）”分析口径，可以查看现在某部门员工的历史用量；也可切换“请求发生时的部门”，继续保留原有历史归属分析。当前口径只是查询视图，员工调部门后该口径结果随之变化，不更新原始汇总中的部门快照。
- 筛选人员使用可搜索下拉，显示姓名、账号、ID；模型选项来自实际使用记录，支持搜索选择。选择条件后点击“查询”生效，选择部门自动切到按人员明细，清空此前人员和模型条件；下钻、周期统计、趋势及 CSV 使用同一批已生效条件。
- 日汇总独立长期保留，清理请求日志不删除汇总。已清理的请求明细无法恢复。
- 本地模型可配置商业对照模型及输入/输出单价，展示“预计避免的商业 API 支出”，不将其称作净节省，不假设商业模型同样会命中缓存，不分摊本地硬件和运维成本。
- 对照价格单位为 USD / 百万 Token，按生效日期匹配。只有超级管理员可新增价格版本，价格只追加，不能覆盖已有版本或回填过去日期；普通管理员可查看。
- 此功能不改变现有定价、钱包、订阅及部门配额的结算。

## 实现和口径

- 主库新增 `usage_analysis_events`（持久化待汇总队列）、`usage_analysis_dailies`（日汇总）、`usage_analysis_states`（历史导入进度）、`usage_analysis_prices`（对照价格版本）。不依赖日志库与主库同库。
- 完成文本等 Token 请求时独立入队，即使消费日志关闭或模型免费也采集；后台每 5 秒处理最多 500 条新请求及 500 条历史日志。
- 队列删除、日汇总累加及历史游标在同一事务中提交；失败回滚，重跑不重复计数。多实例通过状态行锁协调（SQLite 事务冲突由下次重试处理）。
- 首次上线固定历史日志导入上界；导入期间不允许通过原日志清理接口删除旧记录。仅能导入仍保留的日志，导入完成前页面提示数据不完整。所有节点需升级到本版本后，才能完整采集新请求。
- 总 Token = 归一化输入 + 输出；缓存读取、写入是输入子项，不能重复相加。OpenAI 输入通常已含缓存，Anthropic 非缓存输入需要加缓存读取及写入；优先采用显式归一化输入。
- 页面 Token 数值统一以 M（百万）显示，保留两位小数；正数不足 0.01 M 时显示 `<0.01 M`，表格悬停可看原始数量。总量、平均值、明细及图表采用相同单位，请求次数不折算。数据库、CSV 导出和计价计算保留原始 Token 数量及精度。
- 区分实测、估算、来源未知的请求数，并支持按来源筛选 Token。缓存仅有合成零值且无法证实上游提供时保守标为未提供；缓存累计可为部分覆盖，页面同时显示提供缓存数据的请求数。
- 当前周期与平均值受部门、人员、模型及来源筛选影响，但不受所选起止日期影响；起止日期用于范围总量、趋势、明细和节省估算。完整自然月不含首次覆盖的残月；日均/周均使用最近最多 30 个完整日，周均 = 日均 × 7（整数展示有舍入误差）。
- 配置了对照价格的模型归类为本地模型，尚未配置的统一归为其他模型。不推断模型部署位置。对照配置生效前的使用量可见，但不计入节省金额。
- 请求明细跳转到现有消费日志，以人员、模型和北京时间范围筛选；原日志页不提供历史部门或用量来源筛选，那里可能包含该用户同一时期在其他部门的请求。日志已清理时仅剩汇总。
- CSV 包含所选范围总量、当前周期及平均值、每日趋势和所选分组的全部分页结果。以字段名标明 Token、请求数及 USD，字符串防止电子表格公式注入。

## 验证重点

历史日志导入及重跑、关闭消费日志时的免费模型采集、部门快照、不同渠道缓存归一化、独立日志库、汇总事务失败后的恢复、周日及跨月边界、零用量日和平均分母、价格版本不覆盖历史，以及超级管理员编辑权限。

2026-10-19 本地验证：新增后端用例、model/controller/middleware 完整测试通过；前端类型检查、涉及文件 lint、用量分析及原配额页面共 8 个测试、生产构建和 Go 编译通过。service 全量测试仍有原先的两项渠道亲和缓存用例失败：`TestObserveChannelAffinityUsageCacheByRelayFormat_MixedMode`、`TestObserveChannelAffinityUsageCacheByRelayFormat_UnsupportedModeKeepsEmpty`；本次未修改渠道亲和逻辑，相关计费及部门配额定向回归通过。
